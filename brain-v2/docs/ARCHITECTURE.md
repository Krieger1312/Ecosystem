# Архитектура "Мозга" v2

## Философия

Заменить универсальные инструменты, приспособленные под задачу (n8n как оркестратор,
Obsidian как источник правды), на специализированные компоненты, каждый из которых
создан именно под свою роль.

---

## Слой 1 — Хранилище

**Postgres + pgvector** — без изменений от исходного плана.

- Реляционные данные проектов (задачи, статусы, метаданные заявок биддинг-агента и т.д.)
- Векторный поиск по эмбеддингам (Google embeddings, как и планировалось)
- Полный контроль, self-hosted, без vendor lock-in

## Слой 2 — Память и рассуждение

**Graphiti** (open-source ядро, на котором построен коммерческий Zep) поверх **Neo4j**.

Почему не просто вектор-поиск в Postgres:
- Несколько параллельно живущих проектов с **меняющимся состоянием во времени**
  (пример: приоритет биддинг-агента менялся со временем — обычный вектор-поиск
  не различает "было верно тогда" и "верно сейчас", Graphiti хранит факты
  с временными метками и отношениями)
- Полностью self-hosted, Apache 2.0, бесплатно
- Лидирует в бенчмарках temporal reasoning среди open-source решений на середину 2026

**Deepseek** — массовая обработка: извлечение фактов из потока данных, дешёвая
предобработка контента перед сохранением в память.

**Claude** — сложные решения, финальное рассуждение, оценка качества заявок биддинг-агента.

Опционально на будущее: **Letta** для той части системы, где агенту нужно самому
управлять архивной памятью (не взаимоисключающе с Graphiti — могут работать
над разными подмножествами данных).

## Слой 3 — Оркестрация

n8n **не убирается полностью**, но роль сужается:

**Остаётся на n8n:**
- Вебхуки и мониторинг внешних источников (job-борды для биддинг-агента, RSS/API triggers)
- Интеграции с сервисами, где есть готовые ноды (экономия времени на написание кода)

**Заменяет "мозг" (принятие решений, сложная логика):**
- Claude Code как основной оркестратор
- MCP-серверы как инструменты, вызываемые напрямую
- Обычный версионируемый код (Python-скрипты, cron/systemd) вместо визуальных воркфлоу
- **agent-orchestration MCP** — для параллельной работы нескольких Claude Code
  сессий на разных задачах без конфликтов (общая память, блокировки ресурсов)

Опционально на будущее, если понадобится надёжность длинных процессов
(ретраи, чекпоинты): **Temporal** поверх текущего стека.

## Слой 4 — Интерфейс для человека

Obsidian **меняет роль**: из источника правды в read-only витрину.

- Агенты пишут в Postgres/Graphiti, не в Obsidian напрямую
- Периодический экспорт (`scripts/obsidian_export.py`) генерирует markdown-файлы
  для просмотра глазами и использования графа связей
- Опционально: **kepano/obsidian-skills** — если решишь оставить Obsidian
  и как рабочий инструмент, а не только витрину
- **defuddle-based MCP** — чистый способ закидывать веб-контент в память
  без ручной очистки от рекламы/вёрстки

## Слой 5 — Вспомогательные инструменты

- **vibe-kanban** — управление параллельными сессиями Claude Code по разным
  проектам (биддинг-агент, контент-фабрика, Godot, сайты), изоляция через git worktree
- **fallow** — структурный анализ TS/JS-кода для агентов (если есть веб-проекты)
- **Ollama** — резервный локальный инференс на случай offline-режима
  или снижения расходов на простых задачах

## Диаграмма потока данных

```
Внешние источники (job-борды, RSS)
        │
        ▼
    n8n (только триггеры/интеграции)
        │
        ▼
  Claude Code + MCP-инструменты  ◄──────┐
        │                                │
        ▼                                │
  Deepseek (предобработка)               │
        │                                │
        ▼                                │
  Graphiti (Neo4j) ◄──► Postgres/pgvector│
        │                                │
        ▼                                │
  Claude (сложные решения) ──────────────┘
        │
        ▼
  obsidian_export.py → markdown-витрина (read-only)
```
