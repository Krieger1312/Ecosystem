# Freelance Автоматизация — Полный пакет

Реализация 5-слойного конвейера: обнаружение → заявка → планирование →
исполнение → QA, с тремя точками подтверждения человеком и циклом
самоулучшения через память.

Собирается поверх архитектуры `brain-v2` (Graphiti + Postgres) — этот
пакет предполагает, что brain-v2 уже развёрнут или разворачивается параллельно.

## Состав

```
freelance-system/
├── README.md
├── docs/
│   ├── ARCHITECTURE.md       — все 5 слоёв + 3 точки подтверждения
│   ├── IMPROVEMENT_LOOP.md   — 4 механизма самоулучшения
│   └── INTEGRATION.md        — как это стыкуется с brain-v2
├── db/
│   └── schema.sql            — таблицы jobs, applications, decisions, outcomes
├── scripts/
│   ├── discover_jobs.py      — Слой 1: обнаружение вакансий
│   ├── score_job.py          — Слой 1: скоринг по профилю
│   ├── generate_proposal.py  — Слой 2: генерация заявки
│   ├── plan_project.py       — Слой 3: PRD → дизайн → оценка
│   ├── qa_review.py          — Слой 5: финальная проверка перед сдачей
│   ├── track_outcome.py      — запись исходов (выиграл/проиграл/доволен)
│   └── weekly_review.py      — еженедельная ревизия промптов на данных
├── n8n/
│   └── triggers_README.md    — что остаётся на n8n (только триггеры)
└── config/
    └── confirmation_points.yaml — пороги уверенности для 3 точек подтверждения
```

## Порядок разворачивания (как обсуждали — не всё сразу)

1. **Этап 1**: `discover_jobs.py` + `score_job.py` + `generate_proposal.py` —
   слои 1-2, дай поработать 2-3 недели, собери данные
2. **Этап 2**: `qa_review.py` — добавь ревью-чекпойнт на то, что уже
   делаешь руками
3. **Этап 3**: `plan_project.py` — самая трудоёмкая часть, вводи последней

## Важно

Все Python-скрипты — это **скелеты с чёткой структурой**, а не готовый
рабочий код. Реальные запросы к API бирж, Postgres-схеме и Graphiti
помечены как `NotImplementedError` — это сделано намеренно, чтобы
Claude Code дописал их под твою актуальную схему БД и конкретные
источники вакансий, а не работал с чужими предположениями о структуре данных.
