# Архитектура конвейера

## Слой 1 — Обнаружение и квалификация

Источники: RSS Upwork, официальные API других бирж, где доступны.
Намеренно избегаем скрапинга там, где это против ToS (риск бана аккаунта
на старте, когда репутации ещё нет).

Скоринг каждой вакансии учитывает:
- Соответствие профилю/навыкам
- Бюджет и его реалистичность относительно объёма
- Историю клиента (если доступна через API биржи)
- Red flags в описании (паттерны, которые исторически коррелировали
  с проблемными заказами — это поле пополняется через цикл самоулучшения,
  см. `IMPROVEMENT_LOOP.md`)

Результат — запись в таблицу `jobs` (см. `db/schema.sql`) со скором
и причиной скора.

## Слой 2 — Генерация заявки

Few-shot генерация на основе истории **успешных** заявок из Graphiti
(brain-v2), не с нуля. Чем больше накоплено данных о том, что сработало,
тем точнее генерация со временем.

**🔵 Точка подтверждения #1 — отправка заявки.**
Ставки низкие (максимум — не выиграть тендер), поэтому порог автономности
высокий: при высокой уверенности скоринга — автоотправка, при пограничном
скоре — подтверждение у тебя. Порог задаётся в `config/confirmation_points.yaml`.

## Слой 3 — Уточнение и планирование

После победы в тендере: агент собирает требования у клиента, прогоняет
через PRD → технический дизайн → оценку объёма/сроков (паттерн из
shinpr-boilerplate: scope-discoverer → PRD-creator → technical-designer).

**🔵 Точка подтверждения #2 — план и оценка.**
Ставки выше (неверная оценка = либо продешевил, либо не уложился в срок).
Эта точка не автоматизируется полностью даже при высокой уверенности —
её роль в конфиге зафиксирована как `always_confirm: true`.

## Слой 4 — Исполнение

Claude Code + подходящий boilerplate (выбирается по типу заказа) +
цикл под-агентов с самопроверкой (verifier/reviewer, как в
shinpr-паттерне). Для параллельных заказов — vibe-kanban с изоляцией
через git worktree.

## Слой 5 — QA перед сдачей

Автотесты, code-review, для веб — доступность и кросс-браузерная проверка.
Генерация демо-материалов для клиента (скриншоты/запись) как часть пакета сдачи.

**🔵 Точка подтверждения #3 — финальная сдача клиенту.**
Самая важная точка. Всегда `always_confirm: true` независимо от уверенности
системы — репутационный риск и человеческая интонация в коммуникации
не делегируются агенту.

## Финансовый и коммуникационный контур (не автоматизируется)

Выставление счетов, эскроу, споры — только с явным разрешением на каждое
движение денег. Ответы клиенту при недовольстве/резком тоне — черновик
может готовить агент, но отправка — всегда через тебя.
